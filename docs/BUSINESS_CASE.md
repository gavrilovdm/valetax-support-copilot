# Business case — one page

**Question:** what does the co-pilot cost to run at ~10,000 tickets/month, and on which model?

**Answer: Claude Sonnet 5.5** (prompt `triage_v3`, cached prefix), **≈ $84/month** in tokens at 10,000 tickets ($0.0084 per ticket). It handles 94/100 tickets correctly with zero hard-rule violations — the only model at zero under every prompt version and eval set; Opus costs twice as much for no measurable gain. Haiku and DeepSeek are faster and cheaper but break hard rules and handle fewer tickets correctly.

DeepSeek Flash (deepseek-flash) costs $8 instead of $84 a month in tokens: a saving of $77/month. Against that: 4/83 judged drafts break a hard rule where Sonnet has 0, 87/100 tickets handled correctly against 94/100, larger run-to-run variance, and customer tickets sent to a new processor in another jurisdiction (a compliance review, not a code change). Not worth it at this volume; worth re-testing if volume grows 10×.

## Transition: 2 weeks of shadow mode

Drafts are generated for every real ticket but not shown; operators work as usual ([ADR-016](decisions/ADR-016-shadow-mode-rollout.md)). The system costs the full token price with no operator time saved yet: ≈ **$39** for Sonnet at 10,000 tickets/month. Go to assist mode if hard-rule violations stay at 0 on reviewed samples.

## What is in the number, and what is not

- In: eval token counts × list prices (`configs/prices.yaml`), 80% cache hits on the rules + KB prefix, retries included.
- Not in: hosting (one small container), engineering upkeep, and operator savings. Savings need Valetax's operator cost per hour and handling time per ticket, then the shadow-mode measurements (accepted / edited / discarded drafts, handling time before and after).
